# 数据核验、时长候选与正式筛选

## 1. 只读核验

读取前确认本阶段允许的唯一输入；计算 SHA-256，记下实际路径和文件更新时间。阶段 2 的输入必须是指定清洗后文件，不能因读取困难退回清洗前文件。

实际列出所有工作表。用户指定精确表名时，缺失或不一致应停止数据读取并报告，不能猜测相似名称。列出表名不等于读取所有表。数据字典只读允许列；检查真实标题后使用 `usecols` 或等价限定，不能先读全表再丢弃禁止列。

检查重复表头、表头所在行、尾部备注/合计、隐藏行和公式。不要把空白格式行自动当答卷，也不要悄悄丢掉异常记录；先明确有效数据区域。CSV 编码、分隔符和字段类型应核对；旧 `.xls` 缺读取引擎时报告，不擅自转换覆盖。

映射结构建议 `canonical_name -> raw_header`，由数据字典实际内容定位，每个目标恰好匹配一个存在的原始字段。逐项显示字段名、类型、允许值、跳题说明，缺失/重名则暂停相关模块。保留原始 Excel 行号用于审计，不用重排后的 DataFrame index 代替。

正式表格用 HTML 展示必要字段、数据规模、少量脱敏预览和映射。含 IP/联系方式时不展示完整敏感字段；需要“全部字段”是字段名称，不是全部答卷值。

## 2. 时长解析

先检查所有非空原值的格式类型。显式识别带单位的秒、分钟及分秒组合；裸数字只有数据字典/用户确认单位后才能转换。`1:20`、Excel 时间小数、“一分半”等有歧义的格式不能猜。

保留原列，将秒数写入副本的可空数值字段。输出无法解析的原值和必要记录标识；存在未知格式时停止后续时长阈值计算。负数、零、缺失单独报告，不能擅自改值或删卷。核对非空数 = 成功解析数 + 解析失败数；失败为零后再核对成功数与原非空数。

缺失/非正时长的有效性规则尚未确认时，暂停依赖它的筛选，不把 `NaN < cutoff` 的 False 当成“已合格”。不把长时作答自动当作无效答卷。

## 3. 入题路径与特殊编码

每道跳题配置包括：前置字段、实际入题值、后续字段、各字段的跳题值、入题后的合法取值。路径签名是前置题各分支的组合，不改原答案。前置题缺失/非法不能强行归到某一路径。

对每份答卷检查：应入题却全为跳题码、未入题却有后续答案、入题后单个项目超范围。异常表列出原行号/标识、前置题值、后续字段和值，标“跳题逻辑待核查”；本环节不自动删除或修复。

注意 `96` 等数字没有通用含义。例如同一排序题中：未入题者整题为跳题码；入题者某项目为该值，可能表示未排进前三。这一项目仍要使用入题人群分母，不是把该人剔除。不同题目分母有交叠不必然是错误，以确认后的入题条件为准。

## 4. 时长候选分析（仅用户要求时）

总体及路径分别报告 n、均值/标准差、最小/最大、P1/P5/P10、Q1/中位数/Q3、IQR；用户只要其中部分时不强加整套。明确百分位算法和标准差自由度。直方图、箱线图、ECDF、短时局部图只用于该任务；标明秒与分钟，局部截断范围说明清楚。

以下只是可选协议示例，需用户确认后才启用，**不是问卷星通用删除标准**：路径 n≥30 用路径中位数的 1/3、1/2 作为极快/偏快候选；不足时暂用总体参考并标不稳定；长时参考 `Q3+3×IQR`。也可完全不用这些规则。不要自行合并稀少路径，不在候选标记中添加最终删除决定。

候选输出保留原时长、解析秒数、路径、路径 n、所用中位数/阈值/来源、分类、跳题疑点及备注。分类数量需与该分类使用的有效 n 核对。分位数只作辅助，不自动替换用户选定规则。

## 5. 经确认的正式筛选

先得到规则 ID、涉及变量、明确表达式、边界、缺失处理和剔除原因。旧项目的 120 秒、未成年条件、逻辑矛盾、96 处理方式不能直接继承。只有用户批准的规则参与删除；未授权的 IP 重复、直线作答、长时等至多报告，不自动筛掉。

在副本中创建严格布尔规则列，最终无效标记 = 所有已批准规则的 OR。未知值不能隐式转 False。每份答卷只删除一次，日志一行，合并全部规则与中文原因。原始行号不唯一、日志重复、规则未决时不得保存筛选结果。

日志最低包含：原始行号、必要标识、涉及的原答案/时长、解析时长（如涉及）、全部规则 ID、原因、处理结果；不泄露完整 IP。区分规则触发事件数与实际删除答卷数。

若要求保留 Excel 原样：先复制源工作簿，再在副本用 openpyxl 等定点修改；先完整生成日志，再按原行号从大到小删除整行，绝不删除表头、不改列、不重排/重新编号。保留已有工作表，只增加用户允许的日志表。

含公式、表对象、合并单元格、宏、外部链接、图形的工作簿不能假定 openpyxl 删行会自动更新全部依赖。先检查；无法证明保真时报告具体风险，征求适当工具/输出形式，不用 pandas 整表重导掩盖格式丢失。

## 6. 保存与核对

- 保存前确认目标未占用且源文件未被其他程序改变；不是看到锁文件就杀进程。
- 筛选前 n = 筛选后 n + 去重剔除 n；每个剔除者至少命中一项规则；未命中者全部保留。
- 保留答卷的原列值、顺序、原编号完全一致；源文件 SHA-256 不变。
- 重新读取目标，核对工作表集合、数据区域行列数、日志行数、规则/原因非空、字典内容及要求保留的格式属性。
- 检查日志首行加粗、筛选、冻结首行、换行和列宽。阶段输出写清规则版本，完成后停在用户指定阶段。
