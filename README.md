# 问卷星数据分析 Skill

一个面向问卷星及类似平台导出数据的中文分析技能：从字段核验、时长/答题路径检查，到规则筛选、正式统计、图表和可编辑表格、持续返工。不生成论文正文，不预设某份问卷的正确答案或删除标准。

**这是一个覆盖完整问卷分析流程的 skill，不是三个固定功能，也不是把三个外部技能简单打包。** 本文后面的三个代码框只是调用示例，Gemini、去 AI 味和图表美化则是另外三个可选扩展。

本技能为 agent 提供工作规则、分阶段操作说明和可复用代码，由 agent 结合实际文件和运行环境执行。它不是安装后脱离 agent 自动运行的统计软件，也不会替研究者确认筛选标准和统计方案。

说明版本：1.0.1。

## 完整工作流：从数据到成果

数据与方案核验 → 时长和跳题检查 → 按确认规则筛选 → 正式统计 → 图表与表格交付 → 持续返工。

| 阶段 | 主要工作 | 常见产物与停点 |
|---|---|---|
| 0 数据与方案核验 | 实际列出工作表，核对字典、字段映射、输入版本和环境 | 字段/编码核对、待确认问题；不猜字段、不读取禁用列 |
| 1.1 质量候选 | 解析时长、检查跳题与答题路径，按需要做候选分析 | 问题清单、候选标记和时长图；只标记，不自动删卷 |
| 1.2 规则筛选 | 执行已确认规则、OR 去重，在工作簿副本中筛选 | 筛选后文件、逐卷剔除日志、数量核对；不增加删卷条件 |
| 2 正式分析 | 确定各题有效分母，生成衍生变量，执行获准的描述和推断统计 | 可复现 Notebook、全部预定结果及暂停项；不重新清洗或只保留显著结果 |
| 3 成果交付 | 生成研究图表、Excel 结果表、可编辑 Word 表及简短结果说明 | 表格、图片和索引；数字有来源，不写论文正文 |
| 持续返工 | 在既有 Notebook/结果中修改相应模块，更新索引与日志 | 更新后的原成果；统计变化重算依赖，纯搬表不触发全量重跑 |

这些是可以单独进入的任务模式，不要求每次从头跑到尾。已有清洗后数据可以直接从正式分析开始；只改表格时可以只做排版。阶段编号是组织示例，项目可以使用自己的编号和章节名称。

## 核心功能：不依赖三个可选扩展

- **识别真实数据结构**：读取实际字段和允许使用的数据字典，检查缺失/重复映射，不靠固定列号或猜测题目。
- **处理问卷特有的数据口径**：区分跳题、未选中、排序未进入前列与真正缺失；明确每项分析的入题条件、有效 n 和百分比分母。
- **按规则筛选并保留证据**：只执行用户确认的剔除规则，一份答卷只记一行日志，保留原始数据与筛选前后核对关系。
- **计算经确认的统计结果**：复用描述统计、交叉表及方案指定的卡方、U/H、Spearman 等方法；先检查适用条件，失败的项目暂停并报告，不自动换方法。
- **生成可用的成果**：使用实际环境中的统计、绘图和文档工具完成表格、常规图表、Excel/Word 导出与验证。未启用图表美化扩展也能作图，未启用 Gemini 也能提供简短结果说明。
- **维护可复现性和返工记录**：持续维护同一正式 Notebook，区分计算变化与纯排版，核对源文件未被改动，实际运行所需代码，更新索引与日志。

核心能力不等于所有分析都自动执行。评分答案、删卷阈值、分组和统计方案需要本项目的依据或用户确认；没有的内容不能从其他问卷照搬。

## 三个可选扩展：辅助增强，不是主体功能

| 可选扩展 | 负责什么 | 启用方式与边界 |
|---|---|---|
| Gemini 文字辅助（`gemini-writer` 或本包通用适配器） | 简短结果说明、图注、表注等文字整理 | 首次使用询问是否接入 API；未同意不调用；不生成论文正文，不替用户决定统计规则 |
| `lieflat-less-ai-tone` | 检查并减少已有短说明中的模板腔 | 相关需求出现时先询问；先给修改建议，得到确认后再改；不改变事实、数字或必要限制 |
| `lieflat-charts` | 在已核实数据基础上美化图表 | 相关需求出现时先询问；不改变分组、分母或统计结果，保留用户要求的交付格式 |

三项可以分别启用，也可以全部不用。首次询问 Gemini 接入不要求用户必须提供 API，选择“暂不接入”可继续全部本地分析工作。

本包提供可选调用流程和通用 Gemini 适配器，**不包含上述第三方技能的完整实现，也不会自动安装它们**。目标环境已有对应技能时复用；没有时说明缺少什么，再由用户选择安装或继续常规流程。详细授权边界、上游链接和独立许可见 [integrations.md](references/integrations.md)。

## 项目说明和协作规则：推荐使用 AGENTS.md

本技能推荐把希望 agent 长期遵守的项目说明与协作规则写在项目目录的 **`AGENTS.md`** 中。若项目已有 `AGENTS.md`，应保留其原内容，按需要补充或引用分析方案，不要用模板整份覆盖。

文件名并不是使用门槛：

- `AGENTS.md` 是推荐的 agent 协作规则入口，不是所有工具都会自动读取的统一保证；调用时可以明确要求读取它。
- 较长的研究背景也可另放 `PROJECT_CONTEXT.md`、分析方案文档或其他自定义文件，并在 `AGENTS.md` 或当前消息中指明。
- 多个文档存在时先核对适用范围与版本；实质冲突需要澄清，不能仅凭新文件名覆盖旧内容。
- 没有这些文件也能使用：直接在聊天中说明任务、文件和限制即可。仅对影响当前工作的必要信息补问，不因缺一个固定文件名拒绝开始。

### 建议写什么（不是必填表）

| 建议内容 | 可以说明的问题 |
|---|---|
| 研究目标和范围 | 研究什么；当前只做哪一阶段；哪些事情不要做 |
| 输入文件和现有成果 | 哪份文件是当前唯一数据源；工作表/字典在哪里；已有 Notebook、Excel、Word 是否继续复用 |
| 问卷和编码说明 | 题型、选项含义、题目逻辑（如跳题）、特殊编码、已确认的评分答案等 |
| 已确认规则与待定事项 | 哪些筛选/分组/统计方法已批准，哪些还需要询问；不要把猜测写成已确认结论 |
| 输出和呈现要求 | 文件名、输出目录、表图样式、有效 n 和百分比的呈现方式等 |
| 协作与返工约定 | 不改源数据、环境限制、何时重算、日志和索引如何维护等 |
| 隐私及可选功能偏好 | 是否允许调用外部文字服务、允许发送的脱敏范围；不写 API key、token 或其他凭证 |

**不必按上述顺序写，也不必全部填写。** 普通自然语言、几条注意事项、现成项目说明都可以；与项目无关的条目可删，未决定的内容写“待确认”。这些建议仅帮助信息交接，不是统计方案，也不会自动授予删卷、外发或付费调用权限。

需要起点时可参考 [AGENTS.example.md](assets/AGENTS.example.md)。它只是可选模板，不会自动复制到项目中，也不会覆盖已有规则。程序用的 [project_plan.example.json](assets/project_plan.example.json) 是另一份可选配置示例，不要求使用者同时填写两套材料；出现不一致先核对再执行。

## 安装

把 `wenjuanxing-analysis` 整个文件夹放到支持 Agent Skills 的工具的 skills 目录。Codex 常用目录是用户主目录下 `.codex/skills/`；使用自定义位置时遵循该工具配置。目录结构必须是 `skills/wenjuanxing-analysis/SKILL.md`，不要嵌套两层同名目录。重新加载技能列表后即可调用。

此安装包不会自动安装依赖、连接 API、上传答卷、修改云服务或创建项目。安装本技能与启用三个可选扩展是不同的事情。

## 调用示例（仅举例，不代表全部功能）

**下面三个代码框调用的都是同一个 `$wenjuanxing-analysis`。它们不是三个子技能、三个固定按钮或完整功能清单。** 你可以用自然语言说明任意一个上述阶段的任务、输入和限制，不必照抄示例，也不必依次执行这三个例子。

示例一：只做前期核验，不删卷。

```text
$wenjuanxing-analysis
先读取当前项目的 AGENTS.md 和我指定的分析说明，只核验工作表、数据字典和答题时长，
输出候选问题，不删除答卷，不开始正式分析。
```

示例二：修改已有统计口径，重算受影响成果。

```text
$wenjuanxing-analysis
按我已经确认的分析方案，在现有正式分析 Notebook 中修改多选题分母，
重算受影响的表图并更新修改日志，不新增检验。
```

示例三：只搬表和排版，不重新计算。

```text
$wenjuanxing-analysis
只把结果工作簿里的指定表搬到现有 Word，保留数值和表头，
不重算 Notebook，只更新返工索引和修改日志。
```

若没有项目说明文件，把第一句换成“以下是本次任务和约束……”并直接说明即可。首次正式分析、按规则筛选或单独补图同样可以提出，不限于这三个示例。

## 依赖与测试

核心辅助函数/测试仅需 Python 3.10+ 标准库。实际项目按任务选用已有的 pandas、openpyxl、NumPy、SciPy、Matplotlib、Jupyter/nbclient、python-docx 等；缺什么报告什么，不默认安装整套或重建虚拟环境。Gemini 通用适配器仅在获准真实调用时需要 `google-genai`。

在技能目录运行合成测试（不访问问卷、凭证和网络）：

```text
python -B -m unittest discover -s tests -v
```

辅助模块不自动执行统计或修改工作簿；agent 必须按参考文档完成真实数据运行与交付验证。测试通过不代表某个真实研究已通过审核。

API 适配器本地校验（示例保留未授权状态，默认会被拒绝）：

```text
python -B scripts/gemini_text.py --request path/to/approved-local-request.json
```

只有另加 `--send --output path/to/new-result.json` 才允许发起实际调用；输出已存在时拒绝覆盖。不要在聊天、源码或命令行中写入 key。详情见集成文档。
